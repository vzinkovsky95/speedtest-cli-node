# speedtest-cli-node

[![tests](https://github.com/vzinkovsky95/speedtest-cli-node/actions/workflows/test.yml/badge.svg)](https://github.com/vzinkovsky95/speedtest-cli-node/actions/workflows/test.yml)

Консольный скрипт, который замеряет скорость скачивания: делает **10 последовательных запросов** к указанному адресу, дожидается полного ответа на каждый и печатает среднее время запроса, общий объём скачанных данных и скорость скачивания.

Зависимостей нет — только встроенные возможности Node.js (`fetch`, `performance.now()`, `node:test`).

## Запуск

Нужен **Node.js 20 или новее** (`node --version`).

```bash
git clone https://github.com/vzinkovsky95/speedtest-cli-node.git
cd speedtest-cli-node
node speedtest.js <адрес>
```

Пример:

```bash
node speedtest.js https://proof.ovh.net/files/10Mb.dat
```

```
Measuring https://proof.ovh.net/files/10Mb.dat with 10 sequential requests...
Requests:        10
Average time:    146.1 ms
Downloaded:      104.86 MB (104857600 bytes)
Download speed:  574.06 Mbit/s (71.76 MB/s)
```

(Реальный замер с сервера в дата-центре; дома цифры будут другими.)

Адрес должен начинаться с `http://` или `https://`. Удобнее брать тяжёлый файл (картинку, тестовый файл провайдера): чем больше файл, тем меньше на результат влияют задержки установки соединения.

### Без установки — в браузере (GitHub Codespaces)

`Code → Codespaces → Create codespace on main`, дождаться открытия редактора и в терминале выполнить ту же команду `node speedtest.js <адрес>`. Окружение с Node.js описано в `.devcontainer/devcontainer.json`. Учтите: скорость будет замерена у сервера GitHub, а не у вашего компьютера.

## Единицы измерения

| Что | Единица |
|---|---|
| Среднее время запроса | миллисекунды (**мс**) |
| Объём скачанных данных | мегабайты (**МБ**), 1 МБ = 1 000 000 байт; точное число байт — в скобках |
| **Скорость скачивания** | **мегабиты в секунду (Мбит/с)**, 1 Мбит = 1 000 000 бит; в скобках то же в МБ/с |

Мбит/с выбраны как основная единица, потому что в них скорость указывают провайдеры и сервисы вроде speedtest.net. Множители десятичные (10⁶), а не двоичные (2²⁰), — так же, как у провайдеров.

## Как считается

- **Время запроса** — от отправки запроса до получения последнего байта тела ответа. В него входят ожидание ответа сервера и всё скачивание.
- **Объём** — сумма байт, реально прочитанных из тела ответа. Заголовку `Content-Length` скрипт не доверяет: его может не быть или он может не совпадать с фактом.
- **Среднее время** — общее время всех запросов / 10.
- **Скорость** — весь объём / всё время. Это не среднее из десяти скоростей: так один медленный запрос не искажает итог непропорционально.

Детали, которые влияют на точность:

- Скрипт просит тело без сжатия (`Accept-Encoding: identity`): иначе `fetch` прозрачно распаковал бы gzip/br, и посчитались бы распакованные байты вместо скачанных.
- Заголовок `Cache-Control: no-cache` просит промежуточные кэши свериться с сервером. CDN всё равно может отдать файл с ближайшего узла — это обычная работа CDN.
- Первый запрос обычно дольше остальных: на нём DNS, TCP- и TLS-рукопожатие, а следующие запросы переиспользуют открытое соединение (keep-alive).
- Ответ с кодом не 2xx, сетевая ошибка или таймаут (60 с на запрос) прерывают замер: скрипт печатает причину и завершается с кодом 1. Без адреса или с неверным адресом — подсказка и код 2.
- Некоторые сайты отклоняют запросы скриптов (например, Wikimedia отвечает `429`) — тогда скрипт сообщит код ответа.

## Тесты

```bash
npm test
```

Тесты используют встроенный `node:test` и поднимают локальный HTTP-сервер, поэтому не зависят от интернета. Проверяется: подсчёт байт без `Content-Length`, запрос без сжатия, строгая последовательность запросов, ошибка на не-2xx, арифметика отчёта, проверка адреса и коды выхода CLI. Тесты автоматически запускаются в GitHub Actions на Node.js 20, 22 и 24 при каждом пуше.
